# Tech Blueprint
## Internal Talent Marketplace — Prototype
**Audience:** Developer / Technical Reviewer
**Date:** June 2026

---

## 1. SYSTEM OVERVIEW

A web-based internal talent marketplace with six core modules:
1. Mindset / Landing Page
2. Opportunity Board (vacancies, gigs, immersions)
3. Employee Profile Builder
4. AI-Assisted Matching Engine
5. HR/Leadership Dashboard
6. Post-Experience Feedback System

## 3. TECH STACK RECOMMENDATION

### Frontend
| Layer | Choice | Why |
|---|---|---|
| Framework | **Next.js 14** (React) | SSR for fast load; great ecosystem; easy routing |
| Styling | **Tailwind CSS** | Rapid UI building; consistent design system |
| Component Library | **shadcn/ui** | Accessible, customizable components built on Tailwind |
| State Management | **React Query (TanStack)** | Server state caching; async data handling |
| Charts (Dashboard) | **Recharts** | Lightweight, React-native charting |

### Backend
| Layer | Choice | Why |
|---|---|---|
| Runtime | **Node.js** | JS full-stack consistency |
| Framework | **Express.js** or **Next.js API Routes** | Simple REST API; prototype-friendly |
| ORM | **Prisma** | Type-safe DB queries; great DX |
| Auth | **NextAuth.js** | Easy SSO/email auth; session management |
| Validation | **Zod** | Schema validation for API inputs |

### Database
| Layer | Choice | Why |
|---|---|---|
| Primary DB | **PostgreSQL** | Relational data fits this domain well |
| Hosting (DB) | **Supabase** or **Railway** | Free tier, instant Postgres, built-in auth option |

### AI / Matching
| Layer | Choice | Why |
|---|---|---|
| LLM API | **Anthropic Claude API** (`claude-sonnet-4-6`) | Skill extraction + semantic matching via prompt |
| Embedding (optional) | **OpenAI `text-embedding-3-small`** or **Supabase pgvector** | Vector similarity for skill matching at scale |
| Matching strategy (prototype) | **Rule-based + LLM scoring** | Simple and explainable for prototype; upgrade later |

### Infrastructure
| Layer | Choice | Why |
|---|---|---|
| Hosting | **Vercel** (frontend) + **Railway** or **Render** (backend) | Free tier; fast deploys |
| File Storage | **Supabase Storage** or **Cloudinary** | Profile photos, opportunity attachments |
| Email Notifications | **Resend** or **Nodemailer + Gmail SMTP** | Simple transactional email |

## 4. DATA MODELS

### User
```typescript
User {
  id: uuid
  name: string
  email: string
  role: "employee" | "manager" | "recruiter" | "hr_admin"
  department: string
  jobTitle: string
  createdAt: datetime
}
```

### Employee Profile
```typescript
EmployeeProfile {
  id: uuid
  userId: uuid (FK → User)
  aspiration: string           // free text: "I want to lead a team / move into data analytics"
  topSkills: string[]          // e.g. ["project management", "stakeholder engagement"]
  skillsToGrow: string[]       // e.g. ["data visualization", "facilitation"]
  openToOpportunities: boolean
  updatedAt: datetime
}
```

### Opportunity
```typescript
Opportunity {
  id: uuid
  postedBy: uuid (FK → User)
  type: "vacancy" | "gig" | "immersion"
  title: string
  description: string
  department: string
  skillsRequired: string[]
  duration: string             // e.g. "3 months", "1 day", "permanent"
  startDate: date
  endDate: date (nullable)
  status: "open" | "filled" | "closed"
  createdAt: datetime
}
```

### Match
```typescript
Match {
  id: uuid
  employeeProfileId: uuid (FK → EmployeeProfile)
  opportunityId: uuid (FK → Opportunity)
  matchScore: float            // 0.0–1.0, generated by AI
  matchReason: string          // AI-generated explanation
  status: "suggested" | "applied" | "accepted" | "completed" | "declined"
  createdAt: datetime
}
```

### Feedback
```typescript
Feedback {
  id: uuid
  matchId: uuid (FK → Match)
  submittedBy: uuid (FK → User)
  role: "employee" | "host"
  rating: int                  // 1–5
  comment: string
  submittedAt: datetime
}
```

## 5. MODULE SPECIFICATIONS

### Module 1: Mindset / Landing Page
- Static/semi-static content page
- Sections: What is internal mobility? | Types of opportunities | Why it matters | How it works | CTA: Create Profile / Browse Opportunities
- Include pull quotes, icons, and a short animated explainer (optional)
- No authentication required to view; login required to act

### Module 2: Opportunity Board
**Post an Opportunity (Recruiter / Manager):**
- Form fields: Title, Type (vacancy/gig/immersion), Description, Department, Skills Required (tag input), Duration, Start Date, End Date
- File attachment (optional): JD or brief
- Status management: open → filled → closed

**Browse Opportunities (Employee):**
- Filter by: Type | Department | Duration | Skills
- Card view with key details + "Express Interest" button
- Detail modal/page: full description, skills needed, posted by

### Module 3: Employee Profile
- Onboarding flow (3 steps):
  1. Basic info (pre-filled from HR system or manual)
  2. Top Skills (tag input, max 10)
  3. Skills to Grow + Aspiration (free text + tags)
- Profile page: editable, shows match history
- Toggle: "Open to Opportunities" (visible to HR/managers)

### Module 4: AI Matching Engine

**Matching Flow:**
```
1. Employee creates/updates profile
2. System runs matching job (on-demand or scheduled)
3. For each open opportunity:
   a. Extract skills from opportunity description (Claude API)
   b. Compare against employee's topSkills + skillsToGrow
   c. Generate match score (0–1) and brief reason
   d. Store as Match record with status "suggested"
4. Employee sees "Suggested for You" section on dashboard
5. Manager sees "Recommended Candidates" on their opportunity
```

**Claude API Prompt Pattern (Matching):**
```
System: You are a talent matching assistant. Given an employee profile and a job opportunity, assess the fit and return a JSON object with:
- score: float between 0 and 1
- reason: 1-2 sentence plain English explanation of the match

Employee Profile:
- Top Skills: {topSkills}
- Skills to Grow: {skillsToGrow}
- Aspiration: {aspiration}

Opportunity:
- Title: {title}
- Type: {type}
- Skills Required: {skillsRequired}
- Description: {description}

Return ONLY valid JSON. No prose outside the JSON.
```

### Module 5: Dashboard & Reports

**HR / Admin View:**
- Summary cards: Total Opportunities | Active Matches | Completed Experiences | Avg Feedback Rating
- Charts:
  - Matches by opportunity type (bar chart)
  - Match status funnel (suggested → applied → accepted → completed)
  - Top skills in demand vs. top skills employees have (gap chart)
  - Feedback rating distribution
- Filterable by: Department | Date Range | Opportunity Type
- Export to CSV

**Manager View:**
- Their posted opportunities + applicant count + status
- Feedback received on their gigs/immersions

**Employee View:**
- Suggested matches
- Application history + status
- Feedback they've given and received

### Module 6: Feedback System
- Triggered: when Match status changes to "completed"
- Both employee AND host/manager receive feedback prompt (email + in-app)
- Form:
  - Rating: 1–5 stars
  - "What went well?" (open text)
  - "What could be improved?" (open text)
  - "Would you recommend this type of opportunity?" (Yes / No / Maybe)
- Feedback is visible to HR admins; aggregate summary visible to managers
- Individual employee feedback is anonymized in reports

## 10. KEY TECHNICAL RISKS

| Risk | Mitigation |
|---|---|
| AI match quality is poor | Start with rule-based keyword matching; layer AI on top |
| Low employee profile completion | Gamify onboarding; show "X% complete" progress bar |
| Data privacy (employee profiles visible) | Role-based access control; "open to opportunities" toggle |
| No HRIS integration | Manual profile creation for prototype; plan API later |
| Feedback response rate is low | Email reminders; make form short (< 2 min to complete) |
